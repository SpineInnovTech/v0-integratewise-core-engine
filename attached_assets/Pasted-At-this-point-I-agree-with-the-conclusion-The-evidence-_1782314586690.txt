So the diagnosis has narrowed from:

```text
"Something is wrong with memory.propose"
```

to:

```text
"The live memory.propose implementation contains a static SQL binding mismatch."
```

Most likely something like:

```ts
await db.prepare(`
  INSERT INTO proposals (
    id,
    tenant_id,
    title,
    content,
    status
  )
  VALUES (?, ?, ?, ?, ?, ?)
`)
.bind(id, tenantId, title, content, status)
.run()
```

or the reverse:

```ts
VALUES (?, ?, ?, ?, ?)
.bind(id, tenantId, title, content, status, clientId)
```

Those produce exactly:

```text
D1_ERROR:
Wrong number of parameter bindings
```

regardless of payload, tenant, or caller.

What I think is more important architecturally:

### Don't point Customer Zero at `integratewise`

I would not do this:

```text
Customer Zero
↓
integratewise tenant
```

long term.

The platform tenant:

```text
integratewise
```

should become:

```text
Platform
Registry
Shared MCP
Shared Skills
Shared Models
Shared Policies
```

while:

```text
iw-customer-zero
```

should remain:

```text
Customer Zero
Memory
Spine
Research
Tasks
Signals
```

because eventually you'll have:

```text
customer-a
customer-b
customer-c
iw-customer-zero
```

and Customer Zero should behave like a real tenant.

Otherwise you're testing against a special tenant that customers will never use.

integratewise
