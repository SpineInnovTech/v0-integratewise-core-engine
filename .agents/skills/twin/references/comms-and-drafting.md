# Communications & Drafting

How the Twin drafts emails, replies, and messages, triages inboxes, and runs
follow-ups — all as drafts a human reviews and sends. The Twin never sends anything
itself.

## Email drafting — BLUF (Bottom Line Up Front)

State the ask or conclusion in the first line, then the minimal context. The reader
should know what's needed without scrolling.

Subject = action keyword + topic. Useful bracketed prefixes:

- `[ACTION]` — recipient must do something
- `[DECISION]` — recipient must choose
- `[SIGN]` — signature/approval needed
- `[INFO]` / `[FYI]` — no action, read when convenient
- `[REQUEST]` — asking a favor

Structure:

```
Subject: [ACTION] Approve Q2 budget by Fri 5pm

BOTTOM LINE: Need your sign-off on the attached Q2 budget ($142K) by Friday 5pm ET
so finance can close the month.

BACKGROUND:
- $12K over Q1 due to the added contractor (approved in Feb)
- Line 14 is the only new item — everything else is run-rate
- If no response by Friday, I'll assume approved and submit
```

Ground every draft in the real record: pull the contact's last interaction, open
threads, and current status before writing, so the opener is specific, not generic.

## The 5-sentence rule

If an email needs more than ~5 sentences, it probably should be a doc, a meeting, or
a call. Default to shorter — most should be under ~150 words.

## Inbox triage

When the user dumps an inbox or thread, tag each item, then act per tag:

- `REPLY-NOW` — blocking someone → draft the reply in the user's voice
- `REPLY-TODAY` — time-sensitive → draft the reply
- `FYI` — no action → summarize, suggest archive
- `DECISION` — needs the user's input → give a 1-line summary + the options, do **not**
  draft a reply (the user owns the decision)

Always present drafts for the user to review and send — never send on their behalf.

## Follow-up cadence

For "waiting on" items, match tone to elapsed time and draft accordingly:

- Day 2 — gentle nudge: "Just bumping this up your inbox."
- Day 5 — direct ask: "Need this by [date] to stay on track for [reason]."
- Day 7+ — escalate: loop in a manager or propose an alternative path.

Draft the follow-up; the human decides whether to send.

## Output format for drafts

```
Subject: [subject line]

Hi [Name],

[BLUF body]

Best,
[User's name]
```

Match the user's voice and style, not generic corporate speak. Be specific with times
("EOD Friday" beats "soon").

## Slack/Teams messages

Shorter and scannable: bold the ask, use bullets, break with line breaks rather than
headers, keep it under one screen. Same rule — draft it, the human posts it.
