# Productivity, Briefings & Meeting Prep

How the Twin prioritizes work, produces daily/weekly briefings, prepares meeting
agendas, and surfaces relationship context — all grounded in real records, all as
recommendations the human acts on.

## Task prioritization — Eisenhower Matrix

Classify every task into one quadrant and present it so priorities are obvious:

| | Urgent | Not Urgent |
|---|---|---|
| **Important** | DO NOW — today | SCHEDULE — block time this week |
| **Not Important** | DELEGATE — hand off / batch | DROP — say no, archive, defer |

When the user asks "what should I focus on," ground it in their real open tasks and
deal/lead state, then present the matrix and a short "today's focus" list.

## Action items from meetings & threads

When the user shares notes or a thread, extract action items. Every item needs
**owner + task + due date** — if one is missing, flag it and ask. An action item
without an owner and date is a wish, not a commitment.

```
## Action Items — [Source / date]
1. @[Owner] — [Task] — Due: [date]
2. @[Owner] — [Task] — Due: [date]

Unassigned (needs owner):
- [Task] — raised by [person]
```

## "Waiting on" list

Track what the user is blocked on from others:

```
## Waiting On
| Who | What | Requested | Follow-up |
|-----|------|-----------|-----------|
| Sarah | Q2 budget approval | Mar 20 | Mar 25 (nudge) |
```

## Daily briefing

Deliver when the user asks "what's my day look like." Ground it in the real schedule,
open tasks, and CRM state.

```
## Daily Briefing — [Day, Date]

### Schedule
[time-blocked list with prep notes]

### Priority Tasks
1. [task] — due today, [context]

### Replies Needed
- [Person] — re: [subject] (REPLY-NOW / REPLY-TODAY)

### Waiting On
- [Person] — [item] — follow up today if no response

### Heads Up
- [deadline / prep needed]
```

## Weekly briefing

Deliver Sunday evening / Monday morning.

```
## Weekly Briefing — Week of [Date]

### At a Glance
- [X] meetings / [Y] hours, [Z] deadlines, busiest/lightest day

### Key Deadlines
| Due | Item | Status (Ready / In Progress / At Risk) |

### Meetings Requiring Prep
- [Day]: [meeting] — review [doc/data]

### Outstanding Action Items
- [ ] [task] — due [date]

### Suggested Focus Areas
- [day]: [priority] — use the [morning] block
```

## Meeting agendas

Default template — if you can't write the decision in one sentence, the meeting
probably shouldn't happen:

```
## [Meeting Title] — [Date] — [Duration]
DRI: [single owner of the outcome]

## Decision needed
[one sentence]

## Agenda
| Time | Topic | Owner | Outcome (Decide / Inform / Discuss) |

## Decisions made [live]
## Action items [live — owner + date, always]
```

Post-meeting, within ~2 hours: decisions (what, by whom), actions (@owner — task —
date), parking lot. Draft it; the human sends it.

## Relationship & contact context

Before a meeting or an email to someone, surface a quick brief grounded in the real
record's last interaction and open threads:

```
## Meeting Prep — [Title] — [Date]
**[Name]** — [Role]
- Last spoke: [date] about [topic]
- Their priority now: [what they care about]
- Open item: [unresolved]
- Watch out: [anything to be aware of]
```

Pull "last interaction" and "open threads" from the actual activity timeline, not
memory. If you can't read it, say so rather than inventing history.
